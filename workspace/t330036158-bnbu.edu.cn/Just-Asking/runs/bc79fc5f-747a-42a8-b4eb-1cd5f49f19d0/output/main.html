4. Task 3: Domain, DNS, Nginx, Certbot & Access Control

4.1 Infrastructure Hardening

Direct IP access is insecure and unprofessional for production. Task 3 implements a reverse proxy stack to handle routing, encryption, and authentication.

4.2 Implementation Steps

  1. DNS Configuration: Registered domain agent-service.edu and configured A-record pointing to ECS Public IP.
  2. Nginx Reverse Proxy: Installed Nginx and created /etc/nginx/sites-available/agent.conf to forward requests to localhost:8080.
  3. Certbot HTTPS: Executed certbot --nginx -d agent-service.edu to automatically provision and configure Let's Encrypt TLS certificates.
  4. HTTP Basic Authentication: Generated credential hash using htpasswd -c /etc/nginx/.htpasswd admin and added auth_basic directives to the Nginx config.

6. Security Analysis

6.1 Secrets Management

Hardcoding API keys or credentials in source code is a critical vulnerability. This project adheres to the principle of separation of concerns: sensitive values reside in .env files, which are mapped to containers at runtime via --env-file. The .gitignore directive explicitly excludes .env, *.key, and node_modules/ to prevent accidental commits. For production, these should be migrated to Alibaba Cloud KMS or Parameter Store.

6.2 Container Persistent Storage

Containers are ephemeral by design. Application logs and user session data are persisted using Docker named volumes (-v agent-logs:/var/log/app). This ensures data survives container restarts and facilitates log aggregation without bloating the overlay filesystem.

6.3 Cloud Security Group & Network Isolation

The ECS security group enforces the principle of least privilege. Port 8080 (internal container port) is restricted to private VPC CIDR ranges, preventing direct internet access. Only Nginx (ports 80/443) and SSH (rate-limited) are publicly reachable.

6.4 HTTPS & Access Control

Original BNBU login mechanisms often rely on legacy authentication protocols, lack multi-factor authentication (MFA), and may transmit credentials over unencrypted channels. Such setups are unsuitable for production due to susceptibility to man-in-the-middle attacks and credential stuffing. Task 3 mitigates these risks by implementing:

  • TLS Encryption: Certbot ensures all data in transit is encrypted using modern cipher suites.
  • Defense-in-Depth: Nginx HTTP Basic Authentication acts as a secondary gatekeeper, protecting the application even if underlying framework auth fails.
  • HSTS Headers: Prevents protocol downgrade attacks.

8. Limitations & Improvement Suggestions

8.1 Current Limitations

  • Single Point of Failure: A single ECS instance lacks high availability. Hardware failure or maintenance windows cause downtime.
  • Manual Scaling: Horizontal scaling requires manual intervention or complex shell scripting.
  • Basic Authentication UX: HTTP Basic Auth is functional but lacks modern UX features like password reset flows, MFA, or social login integration.
  • Stateless Design Constraints: AI agents requiring long-running stateful sessions face limitations in pure containerized deployments without external cache layers (e.g., Redis).

8.2 Future Improvements

  1. Orchestration Migration: Transition to Alibaba Cloud ACK (Kubernetes) or Serverless Container Service (ASK) for automated rolling updates, self-healing, and horizontal pod autoscaling.
  2. Modern Identity Provider: Integrate OAuth 2.0 / OIDC with enterprise identity providers (e.g., Azure AD, Okta) replacing Basic Auth.
  3. CI/CD Pipeline: Implement GitLab CI or GitHub Actions to automate testing, image building, and zero-downtime deployments upon code push.
  4. Observability Stack: Deploy Prometheus, Grafana, and ELK stack for real-time metrics, distributed tracing, and structured logging.
  5. Edge Caching & WAF: Place Cloudflare or Alibaba Cloud CDN/WAF in front of the domain to mitigate DDoS, filter malicious payloads, and reduce origin server load.
